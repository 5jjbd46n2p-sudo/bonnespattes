# Lot 0 bis : plan d'implémentation

> **Pour les agents :** sous-skill requis : superpowers:subagent-driven-development (recommandé) ou superpowers:executing-plans, tâche par tâche. Étapes en cases (`- [ ]`).

**Objectif :** livrer les quatre points à faible risque du lot 0 bis, chacun sur sa branche.

**Architecture :** modifications locales et indépendantes ; la seule logique nouvelle (export RGPD) est isolée dans une fonction pure testable.

**Pile :** Next.js 16 App Router, `pg`, Bun pour les tests (`bun test`), GitHub Dependabot.

**Spécification :** `docs/superpowers/specs/2026-11-03-lot0bis-design.md`.

## Contraintes globales
- Une branche par tâche, partie de `origin/main` ; jamais de fusion sans « Merge » de Timothé.
- `bun build --no-bundle <fichier>` par fichier modifié ; pas de `node_modules` : les tests n'importent pas `lib/db.js` sans le simuler.
- Aucune donnée personnelle dans les journaux ; vouvoiement côté public ; pas d'emoji.
- Trailers : `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, `Claude-Session: https://claude.ai/code/session_01UDBZYwjhnRcqfgzYGzF2Uu`.

## Points d'attention
1. Export d'un client sans devis ni photo : les nouvelles clés valent `[]`, jamais `null`.
2. Photos : jamais l'URL du stockage privé dans l'export (elle donnerait un accès indirect au fichier).
3. Lien PDF d'un contrat signé il y a 15 à 30 jours : il cesse de fonctionner ; la page `/contrat/[jeton]` affiche déjà l'état « lien expiré » via la même constante.
4. Dependabot : ne doit pas ouvrir une demande par paquet (groupement).
5. Politique de confidentialité : ne pas promettre ce qui n'existe pas (pas de « vos avis sont modérés »).
